# T132: direct guarded method calls (step 4 of the new design, moved first)

Status: done (2026-10-18) | Depends on: T000, T131 | Local (+ a-03 for the gate, after asking)

## Goal
At `o.m(…)` sites where the type analysis (T131) finds one method function `F`, call `F`'s typed function directly
(`direct_call_this`: no argument array, no call through the code table) when a per-site cache says the receiver's
method is still `F`; otherwise today's generic call. User, 2026-10-17: "ok" to doing this before the object layout
(moved to T133), after `probes/layout3.wat` measured direct guarded calls alone 3.1× (V8) / 3.5× (wasmtime) on the
probe kernel with today's objects.

Cost today (laptop, wasmtime, `scratchpad mcall*.js`): a method call ~90 ns (lookup ~50 ns + call ~40 ns) vs a
direct call of a plain function ~15 ns. Method calls per run (T000 counts, all kinds incl. built-ins): deltablue
25.4M, richards 16.6M, raytrace 9.5M, crypto 3.3M, nbody 5.0M.

## Design
- Per site a cache `{keys, proto, holder, slot, hkey, fn, epoch}` (a global per site). Hit (inline): the receiver is
  an `$object`, `o.keys` and `o.proto` are the cached ones (shared layout keys = the shape; `m` was in none of the
  keys at fill), `G_EPOCH` unchanged (keys/prototypes added on the chain, T90), and `holder.keys[slot]` /
  `holder.vals[slot]` are still the cached key and function (catches reassignment, delete, redefinition).
- Fill (helper, on a miss): `m` not in `o`'s keys; found as a data property on the chain; its value a `$function`
  whose code slot is `F`'s adapter: fill, mark the chain `IS_PROTO`; else the generic call.
- Only at sites the analysis types (one receiver group, one target function), whose arguments hold no function or
  class expressions (they're lowered in both branches).
